Vue d'ensemble

Le référentiel est un Google Sheet qui centralise l'affectation des commerciaux par filiale, commune et produit. Il permet aux agents de prise de RDV de savoir instantanément quel commercial appeler pour un client, et déclenche des emails automatiques lors de chaque changement de transfert.

Feuilles de données

  • AFFECTATIONS_COMMUNES — ~9 300 lignes
  • PRODUITS_COMMERCIAUX — ~280 lignes
  • EXCEPTIONS_PRODUITS — cas spécifiques
  • TRANSFERTS — remplacements actifs

Feuilles de référence (cachées)

  • PARAMETRES — listes déroulantes
  • _DDL_TRANSFERTS — cascades commerciaux
  • _COMMERCIAUX_PAR_FILIALE_H — horizontal
  • DPT_SOURCE — 35 000 communes INSEE

Outils utilisateur

  • RECHERCHE — moteur de recherche agents
  • VUE_REGIONALE — pilotage couverture
  • ACCUEIL — documentation

Administration

  • CONTACTS — destinataires emails
  • Menu ⚙️ Transferts — toutes les actions admin

Tâche courante : ajouter un commercial et son secteur

C'est l'opération la plus fréquente. Elle se fait toujours dans cet ordre — un commercial doit d'abord être déclaré dans le référentiel, sinon il n'apparaîtra ni dans les listes déroulantes ni dans les affectations.

1
Déclarer le commercial (obligatoire, en premier) Dans _COMMERCIAUX_PAR_FILIALE_H : repérer la ligne de sa filiale, écrire son nom dans la première colonne vide. C'est cette feuille qui alimente les listes déroulantes en cascade (colonnes B et C de TRANSFERTS).
2
Mettre à jour les listes déroulantes ⚙️ Transferts → Installer les listes déroulantes
Le nouveau nom devient sélectionnable partout (notamment comme remplaçant dans TRANSFERTS).
3
Saisir son secteur et ses produits Ajouter une ligne dans SAISIE_SECTEURS : Filiale | Commercial | Type zone (CP ou COMMUNES) | Zone | Produits. Les CP utilisent la même syntaxe que les TRANSFERTS (33000-33999, 47000).
4
Générer ⚙️ Transferts → Générer les affectations depuis la saisie
Remplit automatiquement AFFECTATIONS_COMMUNES (communes) et PRODUITS_COMMERCIAUX (produits). Vérifier l'aperçu, puis confirmer.
Piège à éviter : si le commercial est saisi dans SAISIE_SECTEURS sans avoir été déclaré à l'étape 1, la génération le signale comme « commercial inconnu du référentiel » et la cascade TRANSFERTS ne le proposera pas. Toujours commencer par _COMMERCIAUX_PAR_FILIALE_H.
Où le commercial apparaît ensuite : listes déroulantes TRANSFERTS (après étape 2) ; AFFECTATIONS_COMMUNES + PRODUITS_COMMERCIAUX et donc le moteur RECHERCHE (après étape 4). Les cas particuliers (EXCEPTIONS_PRODUITS, transferts) restent à saisir à la main selon le besoin.
Pour modifier un secteur plus tard (CP, communes, produits) : on modifie la ligne du commercial dans SAISIE_SECTEURS puis on relance la génération. Ne jamais corriger à la main les lignes « généré » des feuilles produites.

Installation initiale (ou après import Excel)

⚠ Chaque import Excel → Google Sheets réinitialise les listes déroulantes et les déclencheurs. Suivre cette séquence à chaque fois.
1
Ouvrir Apps Script Dans le Google Sheet : Extensions → Apps Script
2
Coller les 3 scripts Créer (ou remplacer) les fichiers notifications_transferts, installer_validations, notes_helper et generer_affectations avec le contenu du dépôt GitHub. Sauvegarder.
3
Fermer et rouvrir le Sheet Le menu ⚙️ Transferts apparaît dans le ruban.
4
Installer les déclencheurs ⚙️ Transferts → Installer les déclencheurs
Active les notifications automatiques (onEdit + rappel quotidien 7h).
5
Installer les listes déroulantes ⚙️ Transferts → Installer les listes déroulantes
Durée : 20 à 30 secondes. Un message confirme la fin.
6
Ajouter les notes d'aide ⚙️ Transferts → Ajouter les notes d'aide
Ajoute les info-bulles au survol dans TRANSFERTS et RECHERCHE.
7
Configurer les emails Aller dans l'onglet CONTACTS :
  • Cellule C6 : mettre TEST pour commencer
  • Cellule C9 : votre vraie adresse email
8
Tester les emails ⚙️ Transferts → Tester l'envoi d'email
Vous devez recevoir un email de confirmation.
9
Diagnostiquer ⚙️ Transferts → Diagnostiquer la configuration
Tout doit afficher ✓. En cas d'erreur, le diagnostic indique quoi corriger.
10
(Optionnel) Protéger les feuilles de référence ⚙️ Transferts → Protéger les feuilles de référence
Verrouille DPT_SOURCE, _DDL_TRANSFERTS, _COMMERCIAUX_PAR_FILIALE_H contre les modifications accidentelles. Améliore aussi les performances.

Configurer les emails en production

Une fois les tests concluants, passer en mode PROD :

CelluleContenu
CONTACTS!C6PROD
CONTACTS!C12 et suivantesUne adresse email par ligne (C12, C13, C14, C15…), autant que nécessaire
En mode TEST, seul l'email de C9 reçoit les notifications.
En mode PROD, tous les emails saisis dans la colonne C à partir de la ligne 12 reçoivent les notifications — sans limite de nombre.
Ajouter / retirer un destinataire : il suffit d'écrire (ou d'effacer) une adresse dans la colonne C à partir de C12. Aucune intervention sur le code n'est nécessaire. Les lignes vides intercalées sont ignorées, et seules les adresses contenant « @ » sont retenues.

Quand un email est-il envoyé ?

  • Dès qu'un transfert passe Actif = Oui → email "Transfert validé"
  • J-3 jours ouvrés avant la date de début → email "Rappel : transfert imminent" (7h du matin)
  • Si un transfert actif repasse Actif = Non → email "Transfert annulé"

Toutes les listes déroulantes sont pilotées depuis l'onglet PARAMETRES.

Plages auto-détectées : il n'est plus nécessaire d'étendre manuellement les plages nommées. Chaque liste est lue de la ligne 2 jusqu'à la dernière cellule non-vide de sa colonne. Ajouter une filiale ou un produit dans PARAMETRES suffit — la plage s'ajuste seule au prochain « Installer les listes déroulantes ».
Après toute modification de PARAMETRES, relancer ⚙️ Transferts → Installer les listes déroulantes pour propager les changements.

Ajouter une filiale

1
Déclarer la filiale dans PARAMETRES Colonne B : ajouter le nom sur la première ligne libre, à la suite des autres. Inutile d'étendre la plage nommée à la main — elle est recalculée automatiquement.
2
Ajouter une ligne dans _COMMERCIAUX_PAR_FILIALE_H Colonne A = nom de la filiale. Les commerciaux viendront en B, C, D… (tu peux les laisser vides pour l'instant et les compléter au fil des informations reçues).
3
Mettre à jour les listes déroulantes ⚙️ Transferts → Installer les listes déroulantes
Recrée les plages nommées (dont PARAM_FILIALES, recalculée jusqu'à la dernière filiale saisie) et toutes les cascades. La nouvelle filiale devient sélectionnable partout.
4
Ajouter ses commerciaux et leurs secteurs Suivre la procédure habituelle décrite plus haut dans « Tâche courante : ajouter un commercial et son secteur ».
Si tu sautes l'étape 3, la plage nommée PARAM_FILIALES pointe encore sur l'ancienne plage (ex. B2:B16) — la nouvelle filiale n'apparaîtra dans aucune liste déroulante malgré sa présence dans PARAMETRES.

Ajouter un commercial

Procédure complète (déclaration + secteur + produits) décrite plus haut dans « Tâche courante : ajouter un commercial et son secteur ».

Peupler les affectations en masse (génération par règles)

Plutôt que de saisir à la main les ~9 300 lignes d'AFFECTATIONS_COMMUNES, on décrit une règle par commercial et un script déplie ces règles contre DPT_SOURCE (35 000 communes).

1
Créer la feuille de saisie ⚙️ Transferts → Créer la feuille de saisie (secteurs)
Un onglet SAISIE_SECTEURS est créé avec deux lignes d'exemple et les listes déroulantes.
2
Saisir une ligne par commercial Colonnes : Filiale, Commercial, Type zone, Zone, Produits.
  • Type CP : même syntaxe que la colonne CP des TRANSFERTS — 33000, 33000, 47000, 33000-33999, mix, ou Tous.
  • Type COMMUNES : liste de noms de communes séparés par des virgules (pour les filiales gérées commune par commune).
  • Produits : liste séparée par des virgules, ou Tous (= tous les produits de PARAMETRES C2:C25).
3
Générer ⚙️ Transferts → Générer les affectations depuis la saisie
Le script remplit AFFECTATIONS_COMMUNES et PRODUITS_COMMERCIAUX, puis affiche un rapport.
Rôle déduit automatiquement : une commune avec un seul commercial → Principal (Priorité 1) ; avec deux commerciaux ou plus → tous Co-affecté (Priorité 2). Il suffit donc de saisir les deux commerciaux sur les mêmes CP, le chevauchement est détecté.
Saisies manuelles préservées : une colonne Origine marque les lignes générées (« généré »). Régénérer ne remplace que ces lignes-là — ce qui a été saisi à la main reste intact. La génération est donc relançable filiale par filiale, au fil des informations reçues.
Le rapport signale : les règles sans commune trouvée (CP mal saisi), les commerciaux sans produit, et les communes partagées entre filiales différentes (à vérifier). Pour le Type COMMUNES, le rapprochement se fait sur le nom (accents et casse ignorés) : si un nom diffère de la référence INSEE (ex. ST vs SAINT), la commune n'est pas trouvée.

Résoudre les problèmes courants

ProblèmeSolution
Les listes déroulantes sont vides après import ⚙️ Transferts → Installer les listes déroulantes
Les emails ne partent pas Vérifier CONTACTS (C6 = TEST ou PROD, C9 = vraie adresse). Lancer "Diagnostiquer".
Menu ⚙️ Transferts absent Fermer et rouvrir le Sheet. Si absent : vérifier que notifications_transferts.gs est bien collé dans Apps Script.
Doublons d'emails sur un transfert ⚙️ Transferts → Réinitialiser l'historique emails (puis confirmer)
Le fichier est lent Protéger les feuilles de référence. Éviter d'éditer DPT_SOURCE. Fermer les onglets non utilisés.
Un commercial a été déplacé/renommé Modifier dans _COMMERCIAUX_PAR_FILIALE_H, puis relancer les validations. Les cellules TRANSFERTS existantes peuvent contenir l'ancien nom : à corriger manuellement.

Sauvegardes et bonnes pratiques

  • Le fichier Referentiel_HomeServe_ES.xlsx sur le dépôt est la référence figée — ne pas le modifier directement, l'utiliser pour reconstruire si besoin.
  • Avant toute modification structurelle majeure, faire une copie du Google Sheet (Fichier → Faire une copie).
  • Les scripts sont versionnés sur le dépôt GitHub — mettre à jour depuis là en cas de réinstallation.
  • Le mode TEST est à conserver tant qu'on n'est pas certain des destinataires PROD.
